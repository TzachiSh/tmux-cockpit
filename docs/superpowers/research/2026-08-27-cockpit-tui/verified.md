# Verification pass: the load-bearing claims, checked

Three adversarial lanes, 2026-08-27, each told to refute. Every verdict cites registry source (`~/.cargo/registry/src/*/`) or a program run on this box; tmux experiments on private sockets only. Rules in [rules.md](rules.md) are corrected where a claim was tightened.

## Rendering and crossterm (scratch crate `verify-render`, bins `wide`, `wrap`, `poll`, `drawn`)

**A. "ratatui-crossterm emits `MoveTo` only when the next cell is not `prev.x + 1`; that breaks after CJK and after VS16." PARTLY.** The mechanism is verbatim (`ratatui-crossterm-0.1.2/src/lib.rs:241-247`: position tracked, width never). But `Buffer::diff` (`ratatui-core-0.1.2/src/buffer/diff.rs:139-179`) skips the covered column after an ordinary wide grapheme (`:166-167`), so the next yielded cell is at x+2, non-contiguous, and a `MoveTo` is emitted: **CJK and emoji-modifier sequences are safe** (`中a` → `ESC[1;1H中ESC[1;3Ha`; `👍🏽a` likewise). For a **VS16 sequence** (U+FE0F) the diff deliberately re-emits the covered trailing column at x+1 (`:158-165`, the "some terminals don't clear the trailing cell" workaround), that passes the contiguity test, no `MoveTo`, and on a terminal rendering it two wide the run after it shifts one column (`⌨️a` → `ESC[1;1H⌨️ a`). Fires only when the covered column's symbol changed since the last frame. Upstream: ratatui#2651 (opened 2026-07-20, closed 2026-08-24 by PR #2721, `if x == p.x + w`), **absent from every published crate** (ratatui-crossterm 0.1.2 is from 2026-06-19). zeroclaw's wrapper: the VS16 branch works (measured: `ESC[1;1H⌨️ESC[0m…ESC[1;2H a`); the CJK `suppress_until` branch is unreachable dead code that would silently drop a real cell if reached. Take the VS16 half only; delete it when ratatui-crossterm > 0.1.2 ships. Separate, unfixable at this layer: East-Asian Ambiguous glyphs (▲) are width 1 to unicode-width and to ratatui, so a terminal configured ambiguous-wide shifts them; the 2-column gutter (rule 28) remains the mitigation.

**B. "crossterm builds its event reader lazily on the first `poll` and caches a failure forever." CONFIRMED.** `crossterm-0.29.0/src/event.rs:149-155` (`static INTERNAL_EVENT_READER: Mutex<Option<…>>`, `get_or_insert_with`), `src/event/read.rs:18-32` (`source.ok()` drops the error into `None`), `:52-59` (every later poll returns `Other`, "Failed to initialize input reader"). What can fail: `tty_fd()` (STDIN if a tty, else `open("/dev/tty")`), the epoll fd, the registry, the SIGWINCH signal pipe (`event/source/unix/mio.rs:36-52`), so ENXIO (no controlling terminal) or EMFILE, indistinguishable in the message. Reproduced: three consecutive `poll(ZERO)` all `Err` under a non-tty stdin, `</dev/null`, and `setsid` (root cause `open /dev/tty: ENXIO`). Inside a real `display-popup -E` on a private socket: pty `/dev/pts/14`, polls `Ok(false)`, raw mode ok, `window_size` 38×10, so not popup-specific; it bites when the popup command loses its controlling terminal (a daemonizing wrapper, a hook, `setsid`), and then the TUI paints and ignores every key. A `poll(Duration::ZERO)` before `ratatui::init()` catches it on a clean terminal and claims the fds first.

**C. "`Terminal::draw` re-reads the size every frame via `/dev/tty`, and a transient failure surfaces a stale errno." CONFIRMED, and worse.** `ratatui-core-0.1.2/src/terminal/render.rs:196` → `resize.rs:64-70` (`autoresize` for Fullscreen and Inline, every frame; Fixed exempt) → `ratatui-crossterm lib.rs:337-340` → `crossterm terminal/sys/unix.rs:86-97`: `File::open("/dev/tty")` per call, `TIOCGWINSZ`, fallback to the stdout fd, then `:99-105` falls back to **two `tput` process spawns** (`:273-286`) and reports `last_os_error()` read after the `tput` exec. Measured with a PATH shim: 8 `tput` invocations for `Terminal::new` + 3 draws, i.e. two forks per frame while the ioctl path fails, and `size()` returned a plausible `Ok((80, 24))` from `TERM` on a box with no tty at all. Real errors: ENOTTY(25), ENOENT(2) from the failed exec, EBADF(9); **none is `Interrupted`/`WouldBlock`**, so an `Interrupted`-only retry catches nothing. In a live popup the ioctl succeeds; a genuinely transient failure is a failed `tput` fork under load; a detached client is permanent. The small consecutive-failure budget reset on success is the right guard.

## Rule corrections from this lane

- Rule 57 now reads: wrap the backend for the VS16 case only, with the byte-level test; delete when ratatui-crossterm > 0.1.2 ships; do not port zeroclaw's CJK branch.
- Rule 50 now reads: `Interrupted`/`WouldBlock` retry is for `poll`/`read` (our SIGUSR1); draw failures need the consecutive budget because their errors are ENOTTY/ENOENT/EBADF; never print `size()`'s errno as the cause; and know the `tput` fallback forks twice per frame while the ioctl path fails.
