## What was measured

- tmux 3.7c, a 20-pane private server, 6,000 `list-panes -a` calls across the fleet format and a `#{q:}` variant: server RSS flat at 3,872 KB, ~3.5 ms a call. The tmux-agent-sidebar #85 leak (a Rust sidebar polling `list-panes -a` with `#{q:}` at 1 Hz, ~2 GB/day) does not reproduce here. A 1 Hz live fleet is safe on this tmux.
- `#{=/N/…:}` takes a format as N (`#{=/#{@w}/…:#{E:@lbl}}` with `@w=6` gives `abcdef…`), and a bare word after the colon is a variable lookup, not a literal. That is what makes the width-aware tab ladder two options and one substitution (chrome.md §3).
- Tab budgets from that ladder (`(width − 61) / windows`, floor 10, cap 34; 61 = status-left ~9 + status-right ~52): 80 columns / 3 windows → 10 (floor), 120 / 3 → 19, 160 / 3 → 33, 160 / 8 → 12. The ladder alone does not save 80 columns: status-right eats 52, so the directory segment has to drop below 100.
- fzf 0.44.1 is what Debian 13 and Ubuntu 24.04 ship; upstream is 0.74.3. Every plain-tier colour key in the shared theme parses on 0.44.1 (`preview-border`, `preview-label`, `label`, `gutter:-1`, `scrollbar`, `query`, `disabled`, hex values); `list-border` does not exist there. A repeated flag: last wins; `--color` merges per key, later wins. Both verified, and both are why `@cockpit_fleet_fzf_options` keeps working unchanged after the theme.
- Fleet rows carry literal tabs between `pad_field`'s padded fields (`tmux-review --fleet | cat -A`), so fzf's 8-column tabstop grid decides the columns, not the caps.
- The live fleet in fzf 0.74.3 with `--style=full`, labelled sections and a `--listen` reload every second: 9 MB RSS, 0.9 % CPU, 8-line script. The preview must not `wrap`: a 200-column pane line folds into `↳` fragments.
- `display-message` inside `display-popup -E` survives the popup closing; on the owner's theme it is painted into the middle of status-right with no separator; a message longer than the client is cut with no ellipsis; `-d 0` stays until a keypress (from the #49 ux lane, reused).

## Decisions the owner has to make

1. fzf floor. Two tiers at 0.63 (today's flags below, the styled set above) with a one-time load message, or stay on the 0.44 set only. Recommendation: two tiers; the plain tier is literally today's screens.
2. Whether the fleet uses fzf's `--tmux` popup (0.53+) instead of `display-popup`. The pickers lane says no (the `-p $SRC_PANE` dance and the `-T` titles are load-bearing); the screens lane says yes for `prefix r` only (run-shell expands `#{pane_id}` on the source pane, the labels carry the title). Recommendation: no, for now; one popup mechanism.
3. `--style=full` boxes inside the tmux popup, or `--header-border`/`--footer` rules only. The measured render (README) shows full boxes fit; the pickers lane calls it a double frame against `popup-border-style`. Recommendation: rules, not boxes, once `popup-border-lines rounded` is set.
4. Glyph options: seven `@cockpit_g_*` overrides with Unicode defaults (both design lanes), and whether `⑂` becomes `` (U+E0A0, Powerline) or `⌥`. Recommendation: ship the overrides, keep `⑂` until a font report.
5. Message prefix `cockpit:` for every `display-message` (replacing `tmux-review:` / `tmux-fixer:`), with the 72-column ceiling. Touches ~40 call sites; mechanical. Recommendation: adopt both; the prefix is what makes the ceiling reachable at all (chrome.md §5: the message is welded into status-right with no separator, so every column of prefix is a column of message), and the cost is one sed over the scripts plus nine `tmux-review:` assertions in `tests/run.sh` — reversible by the same sed. (default named by the orchestrator on silence, 2026-09-01)
6. `pane-focus-in` dropped from the four `refresh-client -S` hooks (`full.tmux.conf:237`). Recommendation: drop it; chrome.md R2 measures the hook at two shell spawns plus ~19.6 ms every time the terminal regains focus, buying at most 2 s of freshness that `status-interval 2` already provides, and restoring it is one line in an example config. (default named by the orchestrator on silence, 2026-09-01)
