# Tablet mode for the board and the panel

Draft design. Target: a tablet in portrait, often over SSH (Termux or similar),
touch plus a soft keyboard, 40-60 columns by 30-60 rows. The floor is 28x12,
the same as the panel's tablet floor. Nothing here is implemented yet.

Mockups were generated by `gen_tablet.py` next to this file, which checks that
every line has the stated width. Glyphs are the ones in `tui/src/theme.rs`:
each is one cell wide.

## 1. Decisions in one screen

- **The board becomes a grouped list in tablet mode.** One row per agent under a
  header for each tmux session. The selected agent opens into a **card**, which
  is today's focused tile at full width: thick border, preview, and in tablet
  mode a row of action buttons. Every other agent stays one row.
- **Mode.** The board reads the same `@cockpit_panel_mode auto|pc|tablet` as
  the panel (auto means tablet under Termux). Tablet mode shows the list, turns
  on the mouse and draws buttons. pc mode keeps today's tiles, and `v` switches
  between tiles and list in either mode.
- **Urgency still wins.** Sessions with an agent that needs you (`▲`) or has
  failed (`✕`) sort first. Inside a session agents sort as today, by
  `(state rank, pane id)`. A collapsed group still shows its most urgent row,
  so folding a session never hides an agent that is waiting on you.
- **One chrome for both screens** (audit 7, Part 3 table). The board gets the
  panel's rounded frame with its title in the top border, `▎` means the
  selection on both screens (tmux's active pane becomes an underlined title),
  `?` is `keys` on both, the footer drops one hint at a time and keeps `?` and
  `q`, and both have the same tablet floor card, 28x12.
- **No key means two things a keypress apart** (audit 10, Part 3). The panel's
  paid keys move off letters that are harmless on the board: retry `r` becomes
  `^R`, best guess `g` becomes `^G`. A bare `r` or `g` in the panel shows a
  2-second note naming the new key.
- **Keyboard first.** Every tap runs a key through `App::key()`, as in the
  panel. `h`/`l` fold and unfold, `z` toggles, `c`/`e` fold or unfold all,
  `/` finds, `u` goes to the next agent that needs you, and digits pick an
  agent by number.
- **The panel's tablet conventions carry over unchanged.** Taps act on the
  press. A tap within 300 ms of a layout change is dropped (800 ms after a
  resume). Confirm and discard pairs sit at the top. Buttons replace the
  footer. The floor is 28x12, and every key keeps working.
- **The board and the panel become one loop.** `f` from the board opens the
  panel. When the panel finishes, whether it inserted, sent, or you pressed
  `esc` on Home, you land back on the board with the same agent selected and a
  one-line note saying what happened. The mechanism reuses the panel's
  `--resume` state-file pattern.
- **Quick answer from the board.** `a` on a `▲` agent opens a sheet with the
  prompt's numbered options. Pick one, confirm with the big `yes` at the top,
  and the board reopens with the agent shown as running. This is the phase-2
  triage overlay (`deliver %N`), shaped to the tablet conventions.

## 2. Why a list and not tiles

At 60x30 today's board shows 5 tiles: header, five boxes of 5-6 rows each, and
the footer (see `board-60.txt`). In portrait the grid is always one column,
since `clamp(width / 48, 1, 3)` is 1 under 96 columns. That leaves a tall stack
of boxes, most of whose rows are blank previews of agents you are not looking
at.

The same 60x30 in list form shows all 12 agents and 4 session headers, plus a
full preview of the one you are on (mockup 4.1). The things you scan for, which
agent, what state, what it is asking and for how long, all fit on one row. The
preview matters only for the agent you are about to act on, so only that agent
gets one.

Tiles stay as the pc default, where 2-3 columns of previews are what fzf cannot
draw ("What it is not" in `docs/tui.md`). The list gains a search, which is
fzf's job on `prefix r`, but it is narrowing over at most a few dozen rows, not
a fleet picker: no fuzzy ranking, no multi-select.

## 3. Anatomy of the board list

### 3.1 Rows, in order

| row | content |
|-----|---------|
| frame title | `╭ board · 12 agents · ▲ 2 need you · ✕ 1 ──╮`, the panel's frame; a filter chip or a 5-second note on the right of the top border |
| group header | `▾ api ───── 4 · ▲1 ●1 ✓1 ○1` (`▸` when folded) |
| agent row | ` 1 ▲  :0  server     Do you want to run npm test?      4m12` |
| card | the selected agent: top border = its row, preview, buttons, bottom border |
| button bar | tablet: `[ find ] [ ▲ next ] [ fold all ] [ keys ] [ close ]` inside the frame; pc: key hints in the bottom border, dropped one at a time, `? keys` and `q close` last (the panel's `footer()`) |

### 3.2 The agent row

| field | 60 cols | 40 cols | notes |
|-------|---------|---------|-------|
| number | 2, right-aligned | 2 | stable for the frame, see 3.5 |
| state glyph | 1 | 1 | colour role below |
| review mark | 1 | 1 | `◆` pending, `↵` sent, as on tiles |
| window | `:idx`, 3 | dropped | the card always shows `sess:idx` |
| title | 10 | 9 | `title`, falling back to the window name, then `(no title)` |
| what | flexible, 33 | flexible, 19 | `▲`: the question (`msg`); `✕`: the error; `●`: `doing`; `✓`: `done` + said; `○`: `idle` |
| age | 4, right | 4, right | `since`; the tile rail's format (`32s`, `4m12`, `1h04`) |

`what` is cut with `…` (`...` in the ascii tier) from the right. The tool line
uses `trunc_middle`, as tiles do. Nothing in the row is a clock except the age,
which never reorders anything.

### 3.3 State: glyph, colour role, ascii tier

| state | glyph | role (`@thm_*`) | ascii | row treatment |
|-------|-------|-----------------|-------|---------------|
| needs-input | `▲` | `needs` (peach) | `!` | glyph and `what` in needs colour, title bold |
| error | `✕` | `error` (red) | `x` | glyph and `what` in error colour |
| running | `●` | `running` (green) | `*` | glyph coloured, text normal |
| done | `✓` | `done` | `+` | dimmed, as `dimmed()` does for tiles |
| idle | `○` | `meta` | `.` | dimmed |
| review pending | `◆` | `sky` | `#` | after the glyph |
| fold open / folded | `▾` `▸` | `accent` | `v` `>` | session name bold in `accent` |
| selected, no card | `▎` in column 0 | `accent`, row reversed | `>` | when the preview is off (`space`); the panel's selection mark |
| tmux's active pane | title underlined | - | underline | was `▎` on tiles, which the panel uses for selection |

The glyph always carries the state, so colour is never the only signal:
`NO_COLOR` keeps the glyph, and the panel's bold/dim/reverse fallback covers
the rest.

### 3.4 Order

1. **Groups:** *hot* sessions first, meaning those with a `▲` or `✕` agent,
   then calm ones, and within each band by session name. Two bands and not a
   full rank, because a session's best rank changes every time one of its
   agents goes from running to done. Ranking by it would shuffle groups under
   your finger all day. A group moves only when it starts or stops needing you.
2. **Agents in a group:** `(state rank, pane id)`, today's `board::order` key
   with no clock in it.
3. **Numbers:** 1..N in display order over all agents, folded ones included,
   so folding never renumbers anything. A number that lands in a folded group
   unfolds it.

### 3.5 Folding

- A folded group shows its header with counts per state, and **its single
  most urgent row** when it has a `▲` or `✕` agent. That row is a normal row:
  selectable, numbered, actionable. A folded group with nothing urgent is one
  line.
- Folds are per session name. They survive refreshes, finds and the trip
  through the panel (it is part of the resume state, see 7.5). They also
  survive closing the board, through a small state file (open question 10.2.2).
- A new session appears unfolded. A session that gains a `▲` while folded stays
  folded: its urgent row appears under the header, and the header goes hot and
  may move up a band. Nothing unfolds by itself, since content appearing under
  a finger is how a tap lands on the wrong row.
- An explicit jump into a folded group unfolds it: `u`, a number, or picking a
  row from a find.

### 3.6 Selection

The selection is a **pane id**, never an index.

- **Refresh:** the same pane stays selected wherever it moves. If it moves, the
  scroll keeps its screen row when it can (the anchor), so the card does not
  jump.
- **Pane gone:** select the row that now holds its old position in the same
  group; failing that, the group's header.
- **Fold its group:** the selection moves to the header, and the group remembers
  the pane. Unfolding with `l` returns to it. If the selected pane is the urgent
  row a folded group still shows, it stays selected.
- **Find:** the selection stays if it still matches, and otherwise moves to the
  first match. Clearing the find keeps whatever is selected.
- **Coming back from the panel, a review or the quick answer:** `--select %N`
  (inside the resume state) restores it, along with its folds and scroll.
- **Headers are selectable** stops for `j`/`k`. On a header, `↵` and `space`
  toggle the fold.

### 4.4 Find

`/` or `[ find ]`. The input is the first row inside the frame, because under Termux
the soft keyboard shrinks the terminal from the bottom. Typing narrows live.
Matching is case-insensitive substring on `sess:idx`, the title, `what` and the
state's word (`needs`, `error`, `running`, `done`, `idle`). Space-separated
terms must all match. The state chips type their word into the box, so
`[ ▲ needs ]` is the same as typing `needs `. Groups with no match are hidden;
groups with a match are shown unfolded for the duration of the find, and their
own folds are kept. `↑`/`↓` move the selection while typing; `↵` (`[ keep ]`)
leaves the box with the filter on; `esc` (`[ clear ]`) clears it.

itself (`┏ 5 ✕  infra:0 · terraform ━━━ 6m ┓`), so a tap that opens it leaves

reach of the second tap of a double tap. Preview height is measured, as the
panel's tall tiles are: 4 rows when the list still fits, down to 1 at the

Quick answer sheet: `1`-`9` pick an option and open the confirm, `↑↓ j k`
move, `↵` opens the confirm for the selected option, `f` opens the panel, `↵`
never sends. Confirm: `y` sends, `n` and `esc` go back.

Every new board key is lowercase (KEYS.md: a Shift chord dies under Caps Lock
or a non-Latin layout). `/` and `-` are on Termux's default extra-keys row;
`c` and `e` are letters for that reason, rather than `-` and `=`.

### 6.2 Board taps (tablet mode only)

| element | tap runs |
|---------|----------|
| `▲ 2 need you` in the header | `u` |
| the filter chip `[ /test ✕ ]` | `esc` (clear the filter) |
| group header | `z` on that group |
| an agent row | select it, which opens its card in place |
| the selected agent's card top or preview | nothing (the second tap of a double tap) |
| card buttons | `↵` `a` `r` `f` `i` |
| button bar | `/` `u` `c`/`e` `?` `q` |
| find chips | type the state word |
| `[ keep ]` `[ clear ]` | `↵` `esc` |
| answer option tile | its digit |
| `yes, send N` / `no` | `y` / `n` |
| wheel | scroll the view 3 rows; the selection stays unless it would leave the screen, then it clamps |
| anything, with `?` open | `esc` |
| anything, under the floor | nothing |

**Guard.** The panel's 300 ms guard, with "new view" widened to "the hit map
changed": a fold, an unfold, the card opening, a find narrowing, a refresh
that reorders rows, an overlay opening or closing. A tick that only changes an
age leaves the hit map alone and starts no guard. After a resume, the first
frame's guard is 800 ms. Keys are never dropped.

**Layout rule**, extended from the panel. What confirms is at the top (the
quick answer's `yes`). Whatever opens it is lower down (option tiles, the
card's `[ answer ]`). A property test from 28x12 to 120x40 checks that no
confirming cell shares a position with the element that opened it.

### 6.3 Panel deltas

| key / tap | does |
|-----------|------|
| `^R` | retry the call (Result, Steps, Error). Was `r`, which is review on the board |
| `^G` | best guess (Question). Was `g`, which is first row on the board |
| `r`, `g` | a 2-second note: `^R retries here · r reviews on the board` |
| `1` on a `▲` agent's Home | the Answer sheet (4.6); every other tile is one digit higher |
| `[ board ]`, and `esc` on Home when opened from the board | back to the board (exit with no action; the loop reopens the board) |
| `[ board ]` when opened directly | action `board %N` |
| `[ more ]` (Compose, keyboard up) | the more sheet; `esc` back to the draft |

## 7. Flows

### 7.1 Board, end to end (keyboard)

1. `prefix w`. The loading frame, then the list. The first `▲` agent is selected
   and carded, because the hot band and the in-group sort put it at row 2.
2. Find an agent:
   - scroll: `j`/`k`, `⇥` to jump group by group, `]` a page;
   - by number: `8`, or `1` `2` for 12;
   - search: `/`, type `test`, `↵` to keep the filter;
   - next that needs me: `u`, again for the next.
3. Fold: `h` folds the selected agent's group, `l` unfolds it, `z` toggles; `c`
   folds all, which leaves the triage view, and `e` unfolds all.
4. Act on the selected agent: `↵` jump, `a` answer, `r` review, `f` panel,
   `i` info.
5. After `a`/`r`/`f`/`i` you return to the board (7.4). After `↵` or `q` the
   popup is gone.

### 7.2 Board, end to end (touch)

1. Tap the Termux extra key that sends `prefix w` (add it next to the
   `prefix f` key in `examples/termux.properties`).
2. Tap `▲ 2 need you`, or `[ ▲ next ]`; or scroll with a swipe (the wheel);
   or `[ find ]`, then a state chip or typing.
3. Tap a session header to fold it; `[ fold all ]` for the triage view.
4. Tap an agent row: its card opens in place. Tap a card button.

### 7.3 Answer from the board, the quick way

1. Board, agent 1 `▲ server` selected.
2. `a` / `[ answer ]`: the sheet with options 1-3.
3. `2` / tap `2 Yes, don't ask again`: confirm, pair at the top.
4. `y` / tap `yes, send 2`: the board writes `deliver %3` with `2` in
   `$COCKPIT_ACTION.text`; the wrapper checks the pane still shows the same
   prompt (the panel's `.cmd` guard, applied to the capture) and types `2`.
5. The board reopens: server still selected, header `sent 2 to api:0 · server`,
   the row now `●`.

### 7.4 Board, then panel, then board

1. Board, agent 1 selected. `f` / `[ panel ]`.
2. The board writes `panel %3` and its resume state (selection, folds, filter,
   scroll, card on/off) to `$COCKPIT_ACTION.state`, then exits.
3. `cockpit-board` runs `cockpit-panel -p %3` in the same popup, with
   `COCKPIT_FROM=board`.
4. Panel Home (5.2), first tile `▲ Answer: Do you want to run npm test?`
   (which opens the same sheet as 7.3).
5. Either:
   - **Explain:** `4`, then `2 What should happen next?`. Busy, then Answer
     (5.6), prompt `1`. `s` / `[ send ]`, then Confirm (5.5), then `y`; or
   - **Compose:** `3`, type `fix the flaky db test then rerun npm test`, then
     `^S` / `[ write ]`. Busy, then Steps (5.4). `s` on step 1, Confirm, `y`;
     Steps reopens with step 1 `✓ sent`; repeat; `esc` to the draft, `esc` home.
6. The panel exits: with an action (`send %3`), which `cockpit-panel` runs, or
   with none (`esc` on Home, `Back to board`, `[ board ]`).
7. `cockpit-panel` writes the outcome (`sent`, `inserted`, `nothing sent: <why>`,
   or nothing) to `$COCKPIT_RETURN`, a file `cockpit-board` passed in.
8. `cockpit-board` reruns `cockpit-tui board --resume <state> --last <outcome>`.
   The board draws the remembered list at once, refetches, and the header says
   `sent to api:0 · server` for 5 s. The 800 ms resume guard drops the second
   tap of the `yes` double tap, which would otherwise land on row 2, a group
   header.
9. `q` anywhere in the panel ends the loop and the popup. `jump` from the board
   ends it too.

`r` (review) and `i` (info) follow the same loop: the board reopens when
`tmux-review` returns.

### 7.5 The resume state

The board reuses the panel's file rules. It is `$COCKPIT_ACTION.state`,
created new with `O_NOFOLLOW` and mode 0600, at most 64 KiB, read back
strictly, and it falls back to a fresh board with a note if anything is off.
Contents: `cockpit-board-state 1`, then the selected pane, the scroll anchor,
card on/off, the filter text, and one `fold <session>` line per folded session.
No tmux write, so `COCKPIT_READONLY` is unaffected.

### 7.6 The panel opened directly (`prefix f`)

1. `prefix f` on a pane (or the Termux extra key). Panel Home, title
   `panel · ▲ api:0 · server`.
2. Same views as 7.4 step 5.
3. After `insert`/`send`, the popup closes and the wrapper's `display-message`
   says `cockpit: sent to %3`, as today.
4. `[ board ]` on Home instead: action `board %3`; `cockpit-panel` runs
   `cockpit-board -p %3 --select %3`; the board opens with that agent selected,
   and the loop of 7.4 applies from then on.

## 8. Contract changes (for #61)

The board's rules are frozen; each of these needs a comment on #61.

- **The hard rule "No mouse on the board"** becomes "on the board and the
  panel only in tablet mode", with the same restore on every exit path.
- The board reads `COCKPIT_PANEL_MODE`. The binding passes it to the board
  popup as it does for the panel. The option keeps its name; the docs say it
  now governs both.
- New board flags: `--resume <state> --last <outcome>` and `--select %N`. New
  action `board %N` from the panel. `deliver %N` gets its text via
  `$COCKPIT_ACTION.text`, like `paste`/`send`.
- New environment: `COCKPIT_FROM=board` (the panel's Close becomes Back to
  board) and `COCKPIT_RETURN` (the outcome file).
- `scripts/cockpit-board` becomes a loop, like `scripts/cockpit-panel`'s
  steps loop. It ends on `jump`, on an exit with no action, or on a failure.
- `board::render()` returns a hit map, as `view::render()` does.
- The 40-column refusal applies to pc tiles only; tablet mode has the 28x12
  floor card.
- The board's popup gets `-e COCKPIT_PANEL_MODE=<mode>`, as the panel's
  binding already passes it (audit Part 3.3). It also opens at the panel's
  tablet size, and with `-B`, no tmux border: both screens draw their own frame,
  and today's tmux title names the client's session, not the agent's (Part 3.2).
- The panel's agent context: `cockpit-board` passes `COCKPIT_AGENT=<sess:idx>\t<state>\t<title>\t<msg>`.
  A panel opened directly reads the same fields itself from the pane's
  `@panestate` and `@panestate_msg`.
- Panel keys: `r` retry becomes `^R`, `g` best guess becomes `^G`; Home's tile
  digits shift by one on a `▲` agent.

## 10. Trade-offs and open questions

### 10.1 Trade-offs taken

- **Urgency vs spatial memory.** Hot sessions sort first, so a group moves when
  it starts or stops needing you, which mockup 4.7 shows after an answer. The
  alternative was alphabetical groups and a pinned "needs you" strip on top. It
  is more stable, but it duplicates rows and costs 1-3 rows on a 12-row
  keyboard-up screen. The two-band key, the anchor and the guard keep moves rare
  and harmless.
- **One urgent row under a folded header, not all of them.** It bounds a folded
  group at 2 rows. A second `▲` in the same folded session shows only in the
  header count (`▲2`). `u` still reaches it.
- **Card on by default.** It costs about 6 rows. On 40x24 with 12 agents the
  list then scrolls (mockup 4.2 at 40 fits only because three groups are
  folded). `space` is sticky for anyone who prefers rows.
- **Digits with a 1 s window for 10+.** That is a clock in input handling. The
  test rule is about never sleeping in tests, so the test passes the clock in,
  as `App::tap(t, now)` does. The cost: `1` then a pause then `2` means 2, not
  12.
- **Repurposing `h`/`l` and `⇥`** in the list layout. They follow tree-view
  conventions (ranger, lf, nvim-tree), where columns do not exist. Tiles keep
  today's meanings, and the help is generated per layout.
- **`i` and `f` still differ between the screens.** The board's `i` is info and
  `f` the panel; the panel's `i` is insert (no Enter) and `f` follow up. These
  are the panel's main verbs, and neither one sends an Enter or spends a call
  by itself (follow up opens a box). The two that did, `r` and `g`, moved. The
  frame title, `board` or `panel`, names the screen you are on.
- **Search on the board** crosses into what `prefix r` does with fzf. It stays a
  substring narrowing; fuzzy ranking and multi-select stay in fzf.

### 10.2 Open questions

1. **Should narrow pc mode default to the list?** At under 96 columns the pc grid
   is one column of tiles, which is the same waste as on a tablet. Proposal:
   `auto` picks the list under 72 columns in pc mode too. Not done here because
   it changes the board for keyboard users who did not ask.
2. **Where do folds persist between board opens?** A file under
   `${XDG_STATE_HOME}/tmux-cockpit/board-folds` keyed by session name (no tmux
   write), or a session user option `@cockpit_board_folded`, which dies with
   the session but is a tmux write through the one write function. The draft
   assumes the file.
3. **Does Termux raise the soft keyboard on a tap while mouse tracking is on?**
   If not, `[ find ]` needs the keyboard key on the extra-keys row. This needs a
   device test.
4. **Quick answer parsing.** The options are read from a capture (`❯ 1. Yes
   2. ...`). That is reliable for Claude Code permission prompts. For anything
   else, the sheet falls back to `[ panel ] [ jump ]`. Should the wrapper
   compare the capture again before typing the digit (proposed in 7.3), or
   compare a hash of the prompt?
5. **Errors in `u`.** `u` mirrors `prefix u` and visits only `▲` agents. Should
   `✕` agents get their own key, or the same cycle after the `▲` agents?
6. **Number stability.** Numbers follow display order, so an agent changing
   state renumbers the rows after it in its group. Today's tiles behave the
   same way. A per-pane number (the pane id's digits) would be stable but long.
7. **The `@cockpit_panel_mode` name** now governs the board. Should it get an
   alias, `@cockpit_tablet_mode`, before more surfaces read it?
