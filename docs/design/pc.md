# PC redesign: the board and the panel

Draft. Design only, nothing in the repo changed. Target: a PC, keyboard first,
board areas 100 to 200 columns wide. Every mockup is exact width (100 or 180
columns, counted with every glyph at 1 column, as the `ascii`-free tier draws
them) and was generated by `gen.py` next to this file, so the widths are
checked, not eyeballed.

Fleet used throughout: 13 agents in 4 sessions. `api` and `web` each have one
agent asking (▲), `infra` has one error (✕), `ml` is quiet. The previews are
invented but realistic; the real capture of the test fleet is empty because its
agents run `sleep`.

Glyphs are today's: `▲` needs you, `✕` error, `●` running, `✓` done, `○` idle,
`◆` review pending. New: `▾`/`▸` open/folded group, `▎` the selection (the
panel's own marker, so both screens mark the cursor the same way), `◂` the pane
your client is on (today's `▎` on a tile, moved to the row's end so it no longer
collides with the selection).

Audit references: `[A1]`-`[A10]` are the ranked top 10 in `audit.md` Part 4,
`[H2]`-`[H5]` its Part 3 handoff points. §14 maps every one to the section
that answers it.

## 0. Decisions in one screen

| question | decision |
|---|---|
| layout at wide widths | **two panes**: a grouped list on the left, one big live preview of the selection on the right. Tiles are dropped (§9.1) |
| when the split applies | board area `>= 96` columns. List width `clamp(w/3 + 8, 40, 64)`: 41 at 100, 64 at 180. Below 96, list only |
| grouping | one group per tmux session, header row `▾ api ──── ▲1 ●2 ✓1` |
| blocked agents | **ordering, no strip.** Sessions sort by their most urgent agent, then name; agents inside a group sort by state, then pane id (today's key, scoped to the group). A folded group **still shows its ▲ and ✕ agents**. The list border counts blocked rows scrolled out of view (`▼ 2 more · ▲1`) |
| a folded group shows | its header with `N folded` and the state counts, plus its blocked/error rows |
| selection | keyed by pane id (or session name on a header), never by index. Survives refresh, reorder, fold and filter (§6) |
| find | `/` filters as you type over session, window, name, state word and message. `↵` keeps the filter, `esc` clears it |
| the panel | **docked in the right pane** when that pane is `>= 100` columns (board area `>= 164`). Narrower, the panel takes the whole board area with a crumb line. Same binary, same process, no second popup (§10) |
| quick answer | `a` on a ▲ agent whose screen shows a numbered menu arms the preview: `1`-`9` picks, `o` opens the panel's Compose for that agent (§5.6) |
| coming back | every action that leaves the board (jump excepted) reopens it on the same agent, folds and filter intact, with a one-line result note (§11) `[A1]` `[H4]` |
| footer | one priority list, dropping one hint at a time, `? help` and `q close` always kept (§12.4) `[A7]` |
| key clashes | the panel's paid `r retry` becomes `^R`; docked, every footer names its screen (§12.2) `[A10]` `[H5]` |

## 3. Find: `/` filter active

`/` opens a one-line field at the top of the list. Each keystroke refilters:
groups with no match vanish, groups with a match are shown open whatever their
fold state (folds come back when the filter clears). Matched text is drawn in
accent and bold (not visible in ASCII). The header's right side keeps the filter
on screen after `↵`: `/ test · 4 of 13`.

Matching: case-insensitive substring, space-separated words all must match,
each against session, `win`, window name, title, state word and the
doing/asked/said text. State words include the aliases `blocked` and `needs`
(needs-input), `error`, `running`, `done`, `idle`, so `/blocked` is the "needs
you" view in one key plus a word. Plain substring, not fuzzy: the board shows
a few dozen rows at most, and a predictable match beats a clever one. `prefix r`
remains the fuzzy fleet list.

While typing, letters type (`q` included), `↑↓`, `^N ^P` and `⇥ ⇧⇥` move the
selection over matches, `⌫` edits, `^U` clears the field, `↵` keeps the filter
and returns the keys to the list, `esc` clears the filter and puts the
selection back where it was before `/`. In the list, `esc` with a filter kept
clears it; a second `esc` closes, as today's "esc closes an overlay, else the
board". `/` again edits the kept query.

## 6. Selection, refresh and folding

1. Selection is `Sel::Agent(pane_id)` or `Sel::Session(name)`.
2. On refresh the list is rebuilt, then the selection is looked up by id. Its
   screen row is held where it was if it still fits (the viewport moves, not
   the cursor), so a session reordering above you does not move your eyes.
3. The selected pane vanished: select the agent now at the same position in
   the same session; that session is gone too: the session now at its
   position; nothing left: the first row.
4. Folding a group whose agent is selected moves the selection to the header,
   unless the agent is ▲/✕ and so stays visible: then it stays on the agent.
5. Unfolding keeps the selection on the header; `l` again enters the group.
6. Filtering keeps the selection if it matches, else the first match; `esc`
   from the field restores the pre-`/` selection.
7. Sessions reorder only when an agent's state changes (the sort key has no
   clock), the same promise today's grid makes.
8. Folds and the kept filter live in
   `${XDG_STATE_HOME:-~/.local/state}/tmux-cockpit/board.state` (folded session
   names, the query, the last selection), so the reopened board of §11 and the
   next `prefix w` look the same. A file, not a tmux option: no write to the
   server, and `COCKPIT_READONLY` skips it.

On open: the selection a returning board was handed (§11), else the first ▲
agent, else the agent on your client's pane, else the first row.

### 9.2 No "needs you" strip

A strip would show every blocked agent twice, put two cursor targets on one
pane, and cost rows on short screens. Urgency ordering already puts the first
blocked agent on row 2, folds cannot hide one, `u` cycles them, and the list
border counts blocked agents scrolled away. Cost: an agent that becomes blocked
moves its session up the list. Selection is by id, so the cursor follows, but
rows do move. `@cockpit_board_order name` (sessions by name) is the escape hatch
if that proves annoying.

### 9.3 Open questions

1. Digits cover the first nine agent rows on screen. With 13 agents, four rows
   have no digit. Alternative: digits jump to session N. Kept as agents for
   compatibility.
2. Should `↵` on a header switch the client to that session (a new
   `session <name>` action verb) rather than fold? Folding keeps the action
   contract `<verb> <pane-id>` unchanged; `space` would then be the only fold
   key.
3. Preview scroll (`^U ^D` over `capture-pane -S`) for a question longer than
   the pane. Not designed; the tail has been enough in every capture seen.
4. Persisting folds per machine (the state file) versus per tmux server.

## 10. The panel on a PC

### 10.1 Docked, full-area, or standalone

| how it was opened | board area | the panel is drawn |
|---|---|---|
| `f` on the board | right pane `>= 100` (area `>= 164`) | **docked**: in the right pane; the list stays on the left, dimmed, titled `sessions · held`, still live |
| `f` on the board | narrower | **full-area**: replaces the board, with a crumb line `board ▸ web:2 docs ▸ panel` on row 0 |
| `prefix f` | any | **standalone**: today's popup, no list, no crumb |

Why docked rather than a second popup: the list beside the panel shows the
target agent's state change live, the selection is already the target (no
`%N` to translate), and the panel's 116-column pane is the size its 120-column
goldens were drawn for. Why the list is held, not usable: the panel owns a draft
and an answer. Moving the board's selection under an open draft would either
retarget it (dangerous) or desync the two halves. `esc` back to Home, then `esc`
again, returns the keys to the list.

Why not dock at 100: the right pane would be 59 columns, the panel's 60-column
layout, and Compose would lose its side column. The full-area panel at 100 is
the 120 golden at 96 inner columns, which reads better.

Implementation shape: the board and the panel are already one binary. Docked
mode calls the panel's view and key handler with the right-pane `Rect`; the
panel's printed action (`paste` / `send`) is printed by the board, which exits;
`scripts/cockpit-board` runs `cockpit-panel`'s paste half and reopens the board
(§11). The hard rule "actions are printed, never executed" holds.

What the panel now knows `[A3]` `[H2]`: docked or full-area, it is the
board's selected agent, so the title is the board's `infra:0 terraform`, Home's
first line is its state and message (`✕ error · terraform plan: state lock
held`), and on a ▲ agent Home gains a first row `1 ★ Answer   <the question>`
that opens Compose with the question as context (Write a prompt and the rest
shift down by one; the board's quick answer covers the menu case). `f` from a
narrow board passes the same facts to `cockpit-panel` as
`COCKPIT_PANEL_FROM=board` plus `COCKPIT_PANEL_CTX=<state>\t<sess:idx>\t<name>\t<msg>`,
and the board's popup now passes `COCKPIT_PANEL_MODE` too `[H3]`. Under
tablet mode the panel never docks: it opens full-area, in tablet mode, because
the board takes no mouse. The board's popup title drops `#{session_name}`,
which named the client's session, not the agent's `[H2]`.

## 11. The combined flow

The return trip is one mechanism. `scripts/cockpit-board` already runs the
board, reads its action line and dispatches. New: after `review`, `panel`,
`info` and `answer`, it runs the board again with
`COCKPIT_BOARD_SELECT=<pane-id>` and `COCKPIT_BOARD_NOTE=<the wrapper's last
line>`. After `jump` it does not (you asked to leave). `q` and `esc` never
reopen. `@cockpit_board_return off` turns the reopen off.

The reopened board draws its first frame from `board.state` before the first
fetch (folds, filter, selection), so it looks like the board you left, not a
loading card.

### 11.1 Board: answer quickly

1. `prefix w`. The board opens on the first ▲ agent, `api:0 server`; its
   question is in the right pane.
2. Read the menu in the preview. `a` arms it.
3. `1`. The board prints `answer %3 1` and exits; the wrapper sends `1` to
   `%3`, then reopens the board on `%3`.
4. Back on the board: `api:0` reads `●`, the footer says `✓ answered 1 to api:0
   server · it is running`. `u` goes to the next ▲, `web:2 docs`.

### 11.2 Board: find, then the panel

1. `prefix w`.
2. Find the agent, any of: `j`/`k` down the list; `5` (its digit); `u` (next
   blocked); `n`/`p` session by session; `/docs ↵`.
3. Optionally fold the noise: `-` folds every group (▲/✕ rows stay), `space` on
   one header toggles it, `=` opens all.
4. `f`. At 180 the panel docks in the right pane, the list held; at 100 it
   takes the board area under `board ▸ web:2 docs ▸ panel`.
5. Home: `2` Compose (or `3` Explain).
6. Type the instruction; `^S` writes it. Busy, possibly a Question, then
   Result.
7. `s` send. Multi-line, so Confirm: `y`.
8. The board prints `send %14 <spool>` and exits; the wrapper pastes and
   presses Enter, then reopens the board on `%14`.
9. Back on the board: `web:2 docs` reads `●`, the note says `✓ sent 8 lines to
   web:2 docs · it is running again, ▲ 1 still needs you`.

Leaving the panel without acting: `esc` from Home (`esc board`) returns to the
list in-process, no reopen needed, selection unchanged.

### 11.3 Board: explain an error

1. `prefix w`, `u` twice or `/error ↵`: `infra:0 terraform`, `✕`.
2. `f`, `3` Explain. The Answer explains the lock and drafts a prompt.
3. `s` sends the prompt (one line: no Confirm), or `f` follows up.
4. Back on the board on `infra:0`, state `●`.

### 11.4 `prefix f` without the board

1. `prefix f` on a pane. The standalone popup, today's Home rows and digits;
   at `>= 110` the two-column Home with the screen on the right.
2. Compose or Explain, Result/Steps/Answer, `i` or `s`, Confirm when needed.
3. The popup closes and the wrapper pastes, as today. No board is opened: you
   were never on it.

### 11.5 Handoff contract

| from | printed line | wrapper does | then |
|---|---|---|---|
| board `↵` | `jump %N` | `tmux-jump` | stays in the pane |
| board `r` / `i` | `review %N` / `info %N` | `tmux-review` | reopens the board on `%N` |
| board `f` (narrow, or `@cockpit_panel_dock off`) | `panel %N` | `cockpit-panel -p %N` | reopens the board on `%N` |
| board `f` docked, then `i`/`s` | `paste %N <spool>` / `send %N <spool>` | `cockpit-panel`'s paste half | reopens the board on `%N`, note from its last line |
| board quick answer | `answer %N <digit>` | `send-keys -t %N <digit>` | reopens the board on `%N` |
| standalone panel `i`/`s` | as today | as today | nothing |

`answer` is the verb #61 reserved as `deliver`; this design uses `deliver`'s
slot only for a digit, and #61's inline reply overlay remains the larger
version.

## 13. Trade-offs and open questions, combined

- **Reopen latency.** The return trip is a new process and a fresh fleet read
  (380 ms measured). The first frame comes from `board.state`, so you see the
  old list at once and the new states a beat later. The alternative, a board
  that never exits, would have to run the paste itself and break "actions are
  printed".
- **The held list.** Docked, the list cannot be used while the panel is open.
  A user who wants to fire the panel at two agents does it twice. Accepted:
  a draft must have exactly one target.
- **`a` changes.** On a ▲ agent it no longer jumps. `↵` still jumps, and the
  footer's `↵ answer` on a ▲ row keeps that meaning visible.
- **Quick answer parses a screen.** A numbered menu is detected from the
  capture (`❯ 1.` and siblings). A misread is the risk; the footer spells each
  option it found, and anything it cannot read falls back to Compose.
- **Two widths of panel.** Docked at 164+, full-area below. Tests: the panel
  goldens gain `-dock-180` and `-full-100` variants; the 40/60/80/120 goldens
  must not change.
- Open: should a standalone `prefix f` at a wide terminal offer `w` to open
  the board docked around it? Not designed.
- Open: the board has no tablet mode `[A8]`. Out of scope for a PC design;
  this layout (one row per agent, one action strip) is a better base for one
  than the grid was.
- Open: `@cockpit_board_return` default `on` changes what `r` from the board
  does today (you end on the board, not the pane). Worth a release note.
